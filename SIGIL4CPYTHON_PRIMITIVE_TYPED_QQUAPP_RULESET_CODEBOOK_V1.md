# SIGIL4CPython Primitive-Typed QQUAPP Ruleset Codebook V1

Canonical identifier: SIGIL4CPYTHON_PRIMITIVE_TYPED_QQUAPP_RULESET_CODEBOOK_V1.

This is the public dependency-free codebook replica boundary between canonical
SIGILBOOK and sigil4cpython. It is not a mirror of all SIGILBOOK source.

Canonical publication pattern:

PYKARA_CARVE -> KIRBY_REWRITE -> SWALLO_SWALLOW ->
QQUAPP_PULL_TENSOR_PUSH -> KRONE_TYPED_GATE -> public codebook ->
PACAPDG -> UAP -> SAFE_REPLAY -> sigil4cpython -> CPython public API.

KOKOMPI is a design pattern, not a person identity or authority owner.

Every type-level carrier in this primitive is simultaneously PluralTyped,
ResourceTyped, RelationTyped and QUNOTyped. This applies to public codebook
entries, resources, relations, KRONE gates, KOKOMPI patterns, guided
configuration spaces and the GitHub ruleset projection.

The public codebook stores only public type/interface IDs, public digests,
capabilities, QUNO, resource/relation references, canonical source commit pins
and public schema IDs. Private SIGILBOOK semantic payload is forbidden.

The guided DIY configuration space exposes four finite axes:
ABI_TRACK = PURE_PYTHON | ABI3 | ABI3T;
CPYTHON_MINIMUM = 3.10 through 3.15;
PUBLICATION_PROFILE = LIBRARY | RESEARCH | DEMO;
EXECUTION_BOUNDARY = METADATA_ONLY | NATIVE_EXTENSION_PLAN.

KRONE validates the finite selection. ABI3T requires CPython 3.15 or newer.
A configuration occurrence is a source plan, not native execution.

The public native boundary remains Python.h, Limited API, Stable ABI,
multi-phase extension initialization and typed PyCapsule. Include/internal,
Include/cpython, _Py symbols, PyUnstable APIs and CPython object layout are not
SIGIL contracts.

GitHub rulesets are repository-governance projections, not UAP or semantic
proof objects. Live inspection on 2026-10-06 returned zero repository rulesets.
Classic branch-protection state could not be read through the connected GitHub
App, so no claim is made about classic branch protection.

Recommended V1 ruleset for exact branch main:
ACTIVE; empty bypass list; restrict deletions; require linear history; require a
pull request with one approval and stale-review dismissal; require the status
check named "Validate primitive typed publication codebook"; block force pushes.

Signed commits, code scanning, code quality and coverage are intentionally
deferred until their paths are stable for both SIGIL publication changes and
CPython upstream synchronization.

A dedicated always-running PR-to-main publication check is preferable because
the existing UAP and KQC workflows have path filters. A path-filtered workflow
should not be made globally required unless it is guaranteed to run.
